### Certified composition: the release launch

```text
java -javaagent:plugins/AchieveToDo-Purpur-mc26.3+0.4.0.jar -jar purpur-26.3-2660.jar --nogui
```

- The plugin derives everything else and logs `ATD_LAUNCH_PROFILE=release; derived=[...]`,
  `ATD_GAMEPLAY_MODE=RELEASE` and, once ready, `ATD_PRODUCT_GAMEPLAY_READY=true`.
- For a preset other than NORMAL, the documented first-start option `-Dachievetodo.progression.initialConfig=<preset>`
  is added on a fresh install. EASY, HARD and CHAOS were certified exactly that way.
- Client and plugin versions must match. The world uses BACAP 1.21.1 with the bundled override pack.

## Method

The same seven criteria as 0.3.0: E1 source map, E2 native locked/allowed, E3 real online client, E4 coverage,
E5 reload, E6 hashes and replay, and ReleaseLaunch. Each group needs all seven and an independent reviewer's certificate.

What changed in the harness (rc.4, `tools/certification/rc4/harness/`):

| Change | Why |
|---|---|
| test runtime on Purpur 26.3 build 2660, BACAP 1.21.1 world packs, Prism client on 26.3, input driver rebuilt for 26.3 | the port |
| villager trade oracle `swingSource=PREDICTED` | 26.3 renamed `SwingSource.CLIENT` to `PREDICTED` |
| new group `landmark_abandoned_camp_26_3` (camp located by the `#minecraft:abandoned_camp` tag) | new 26.3 structure and ability |
| new group `landmark_denial_criteria_26_3`: a map into an item frame and a golden dandelion on a tadpole inside a locked igloo; any criterion on a locked row fails it | known issue 6 audit |
| the cartographer locked rows must show the lock message | known issue 5 |
| room coordinates computed, not written as `{v}.5` (wrong for negative coordinates); audit probes run at the player | rc.4 smoke findings |
| rc.4b: the audit room is cleaned after each row and the tadpole gets air; BACAP tallies alone (`bacap/advancement_legend`, `bacap/*_milestone`) are recorded as `bookkeeping`, not as a leak | the 4 harness-caused failures of campaign51/53 |

**Smoke runs before the campaign.** The rc.4 smoke run (one NORMAL runtime with the new cases) found three product
bugs. Each was fixed and a new candidate was built:
- rc.1: the advancement visibility agent called `DisplayInfo.isHidden()`, a record accessor `hidden()` in 26.3, on every
  player tick;
- rc.2: the plugin's native landmark capture did not list the abandoned camp structures;
- rc.3: the 26.3 golden dandelion age lock was not denied inside a locked landmark (known issue 8).

rc.4 passed the smoke run 17/17 and one runtime per preset (campaign56-59) with the camp thresholds 93 / 148 / 457 / 121.

### Independent review

Ten fresh reviewers, 1–9 groups each: 59/59 CERTIFIED in the first round, no blocker or major finding.
The certificates are in `tools/certification/rc4/results/certificates/`. The minor findings, in short:

- **No explicit server denial line** for many native guards (the Bukkit event says `ALLOW` because the guard works at
  bytecode level), and the state line logs `null` for many abilities. The lock is shown by the unchanged count, the
  missing effect, the client's lock message and, for entity uses, `ATD_CRITERION_SUPPRESSED`.
- **Harness provenance:** `campaign.py` and `campaign_cases.py` were edited for rc4b after campaign55. The files that
  produced campaign51-55 were rebuilt byte for byte (`harness/history-rc4a/`, `HARNESS_RC4A.sha256`); they match the
  hashes in those runtimes' evidence.
- **Masked rows:** 4 locked rows were masked by another locked ability (Custom vision for food and jump, CHAOS chest,
  HARD golden tools). Each ability has proving locked rows in other runtimes.
- **Labels and coverage notes:** a stale vision case label; no off-hand rows for the two audit cases (the landmark guard
  does not depend on the hand); the dispenser fixture's own `redstone/click` criterion is excluded by design
  (`fixture_criteria`); golden tools on EASY, CHAOS and Custom show no lock message (`PASS_NO_OVERLAY`).

## Product changes covered by this certificate

See [known-issues.md](../known-issues.md).

1. **Minecraft 26.3.** The mod, the plugin and all native agents are ported; BACAP 1.21.1.
2. **Abandoned camp** (26.3 structure) is a lockable landmark: `interact_inside_abandoned_camp`, thresholds
   EASY 93 / NORMAL 121 / HARD 148; existing worlds get it added to their config.
3. **Cartographer lock message** shows at once (known issue 5).
4. **Denied interactions do not count for use criteria** (known issue 6): the audit rows gain no criterion while locked.
5. **Golden dandelion age lock** is denied inside a locked landmark (known issue 8).

## Limits

- The certificate covers the composition above and the three hashes.
- Presets other than NORMAL ran one case per group.
- The water bucket can look empty on the client for a moment right after joining (known issue 7, by design).
- The landmark border rendering, the advancement screen layout and the SDL file dialog are client presentation and are
  not part of this runtime certificate.
- Minecraft 26.3, Purpur build 2660 and BACAP 1.21.1 as installed in the test runtime.
