### Certified composition: the operator launch

The server is started the way the operator guide describes
([STARTING_THE_SERVER.md](../../port/AchieveToDo-Purpur-26.2/STARTING_THE_SERVER.md)), with one extra Java option:

```text
java -javaagent:plugins/AchieveToDo-Purpur-26.2-0.2.1.jar -jar purpur-26.2-2620.jar --nogui
```

- The plugin derives everything else itself, and logs it as `ATD_LAUNCH_PROFILE=release; derived=[...]` followed
  by `ATD_GAMEPLAY_MODE=CERTIFICATION`. This covers the certified mode and switches, the BACAP folder, the server
  id, the world binding and, on a first start, the progression config.
- For a preset other than NORMAL, the documented first-start option
  `-Dachievetodo.progression.initialConfig=<preset>` is added on a fresh install. EASY, HARD and CHAOS were
  certified exactly that way.
- A start without the agent stops the server with the correct command (`ATD_STARTUP_FAIL_CLOSED`) instead of
  running the uncertified legacy path. The legacy path is opt-in only (`-Dachievetodo.gameplay.mode=diagnostic`)
  and is not certified.
- The 14-flag explicit command certified for 0.2.1-rc.1 still works unchanged. It is not part of this certificate.

## Method

The method is the same as for rc.1: E1–E6, each group must meet all of them, and an independent reviewer must
certify it. The 0.2.1 review adds a seventh criterion, **ReleaseLaunch**. Each runtime that contributed rows must
use the operator launch above, with no hand-set `-Dachievetodo.*` option except `initialConfig` on a fresh install.
It must also log the release profile and the CERTIFICATION mode before its first case.

The oracles were strengthened after the first rc.2 review round. The harness is in `tools/certification/rc2/harness/`.

| Rule | Why |
|---|---|
| `expect_hit`: an aimed case whose client aimed at nothing is `INVALID_FIXTURE_AIM` (retried once per pass) | a missed aim was once counted as a lock proof |
| `server_reach`: vehicles, villagers and the wandering trader must leave a traced `Player.interactOn` return | proves the request reached the server guard, not only the client mod |
| vehicle probe `on vehicle`; villager trade decision `swingSource=CLIENT/NONE` | server-side effect oracles |
| a `client:` oracle already true before the action is `INVALID_FIXTURE_PRESET` | a creative portal crossing once happened during the setup |
| reverse bundle route (item on the cursor onto the bundle) is its own case | the second native route had no rows |

The two supplements and why they exist:

- **campaign36:** the `ignite_tnt` fixture lights the TNT with flint and steel. In that CHAOS world flint and steel
  unlocked later than `ignite_tnt`, so the allowed phase was denied by the flint guard. The case now declares
  `requires=['use_flint_and_steel']`.
- **campaign38:** in campaign31 a creative player stood inside the portal and crossed during the setup. The fixture
  now steps into the portal during the measured window and uses `locked_margin=2`. Touching the portal earns vanilla
  `story/enter_the_nether` for the guard-exempt creative player, and the margin keeps the ability locked when that
  player crosses. An earlier attempt at this supplement, campaign37, was rejected by review and is listed separately
  in the evidence index.

Raw logs stay outside git. [EVIDENCE_INDEX.json](../../tools/certification/rc2/results/EVIDENCE_INDEX.json) records
the SHA-256 of every receipt file of the final runtimes, of the aborted login attempt and of the rejected campaign37.
Frozen harness versions are recorded in `HARNESS_RC2C`, `RC2D` and `RC2F.sha256`. The exact `campaign.py` and
`campaign_cases.py` that produced campaign31-35 are kept byte for byte in `harness/history/*.rc2c`.

### Independent review

- **First rc.2 round (round a):** 57/57 NOT_CERTIFIED. The EASY, HARD and CHAOS worlds had been prepared with a
  hand-set `freshConfig` flag instead of the operator path. The round also produced four evidence-depth findings:
  missed aim, no server-side proof for vehicles and villagers, and the untested reverse bundle route. All were
  fixed, and the whole campaign ran again. Round a is kept in `results/round-a/`.
- **Round c:** eight fresh reviewers. 56/57 CERTIFIED at once. The portal group took two more rounds: round 1 found
  the creative crossing during setup, round 2 rejected campaign37, and round 3 certified it. All are in
  `results/certificates/`.

## Product observations (parity with the Fabric original, not port defects)

See [known-issues.md](../known-issues.md).

1. **Portal contact advancements.** Touching a locked End portal or end gateway is denied, but grants the vanilla
   `enter_block` advancement (+1).
2. **CHAOS thresholds are not reproducible from the seed** across JVM starts.

## Limits

- The certificate covers the composition above and the three hashes. PRODUCT mode, which needs a deployment
  certificate capsule, and the legacy path are not covered.
- Some routes are proven only from the source, with no runtime case: armadillo brushing, chestplate and leggings
  slots, drag-placement, off-hand boots and portal exemptions. They are listed in the findings register.
- Minecraft 26.2, Purpur build 2620 and BACAP compat_26_2_r19 as installed in the test runtime.
- Online logins depend on Mojang's session server, which throttles repeated logins. It refused several attempts
  during the campaign. Those attempts contribute no rows; they are recorded as login failures.
