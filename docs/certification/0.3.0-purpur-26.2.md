### Certified composition: the release launch

```text
java -javaagent:plugins/AchieveToDo-Purpur-26.2-0.3.0.jar -jar purpur-26.2-2620.jar --nogui
```

- The plugin derives everything else and logs `ATD_LAUNCH_PROFILE=release; derived=[...]`,
  `ATD_GAMEPLAY_MODE=RELEASE` and, once ready, `ATD_PRODUCT_GAMEPLAY_READY=true`.
- For a preset other than NORMAL, the documented first-start option `-Dachievetodo.progression.initialConfig=<preset>`
  is added on a fresh install. EASY, HARD and CHAOS were certified exactly that way.
- 0.3.0 has only this mode: the diagnostic legacy path, the PRODUCT certificate capsule and the 16-player cap are
  removed. Client and plugin versions must match.

## Method

The same seven criteria as 0.2.1: E1 source map, E2 native locked/allowed, E3 real online client, E4 coverage,
E5 reload, E6 hashes and replay, and ReleaseLaunch. Each group needs all seven and an independent reviewer's certificate.

What changed in the harness (rc.3, `tools/certification/rc3/harness/`):

| Change | Why |
|---|---|
| marker waits (`Server.sync`) instead of fixed sleeps | the campaign took 4 h 32 min instead of 8 h 50 min |
| EASY, HARD, CHAOS and Custom run one case per group (`--sample one-per-group`); NORMAL runs every case | presets change only thresholds; the full route set runs once |
| `overlay_text`: the shelf denial must name the shelf | user request 4.2 (shelf message) |
| new cases: shears on mooshroom, snow golem, bogged, wolf and cobweb; sword, axe, shovel, hoe; armadillo brush; chest and legs slots; boots from the off hand | routes that 0.2.1 proved only from the source |
| portal cases expect no enter_block advancement while locked | known issue 3 fixed in 0.3.0 |
| chat hover check (`presentation-results.jsonl`) | user request 4.1 (chat hover on Purpur) |
| rc.3b: wait until the bridge sent the new count to the client (`await_count`); `creative=False`, `offhand=False` case flags; `NA_VANILLA_NO_CREATIVE_ROUTE` | the 4 harness-caused failures of campaign41 |

### Independent review

Eight fresh reviewers, 7–8 groups each: 57/57 CERTIFIED in the first round, no blocker or major finding.
The certificates are in `tools/certification/rc3/results/certificates/`. The minor findings, in short:

- **No explicit server denial line** for many native guards (the Bukkit event says `ALLOW` because the guard works at
  bytecode level). The lock is shown by the unchanged count, the missing effect and the client's lock message.
- **Masked rows:** 4 locked rows were masked by another locked ability (Custom vision, CHAOS chest, HARD negative-y
  mining). Each of those abilities has proving locked rows in other runtimes.
- **Harness bookkeeping:** the `campaign.py` hash in the evidence hashes of campaign41-45 is that of rc.3b, taken
  after the run; the rc.3 file that produced the rows is kept byte for byte in `harness/history-rc3/`.
- **Product notes:** the cartographer trade denial shows no lock message (the trade is still denied); after a reload
  the water bucket can briefly look empty on the client.

## Product changes covered by this certificate

See [known-issues.md](../known-issues.md).

1. **Portal contact advancements fixed.** A locked nether portal, End portal or end gateway is denied and grants no
   `enter_block` advancement.
2. **CHAOS thresholds are reproducible from the seed** (one `chaos_20261116` config in E1).
3. **Shears on a snow golem or wolf** no longer grant an advancement while locked.

## Limits

- The certificate covers the composition above and the three hashes.
- Presets other than NORMAL ran one case per group.
- Landmark denials that return SUCCESS were not audited for an advancement leak (known issue 4); reviewers saw none.
- Minecraft 26.2, Purpur build 2620 and BACAP compat_26_2_r19 as installed in the test runtime.
