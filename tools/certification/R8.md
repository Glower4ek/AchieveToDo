# R8 pre-publication tooling

No public push, tag, PR, release, deployment, or version transition is authorized.
The proposed next version is **0.2.1-rc.1**, subject to owner review; v0.2.0 already
exists remotely. Runtime metadata stays 0.2.0-dev.s3c in the private candidates.
PRODUCT_GAMEPLAY_READY remains false.

`r8_network.py` provisions the original 372 selected cache identities using HTTPS
origins and freshly generated Gradle descriptors. Supply an external Gradle 9.8.0
launcher and its SHA-256 explicitly, Java 25 through JAVA_HOME, and distinct
external home/work/output directories. It never reads the offline input bundle.
It enables IPv4 only for the isolated Gradle JVM; TLS and final historical pins
remain enforced. On failure inspect downloads.json, gradle.log, verification.json.
Resume revalidates existing bytes; a substituted destination is refused.
The unchanged historical Gradle metadata policy does not checksum POM files;
final selected descriptor identities still must match their original SHA-256.
Keep supplemental metadata provenance and compare it across independent runs.

`r8_release.py` creates private notice-only candidates from the exact accepted
Fabric/Purpur JARs. Supply an inventoried Purpur source mirror's resource directory
containing META-INF/NOTICE-R8.txt and the exact upstream UI MIT text. This repairs
the false blanket ARR-absence statement in the Fabric component notice and adds
narrow Purpur notices. It does not establish missing BACAP/ARR/port rights.
All gameplay, localization, metadata, and compiled class payloads are preserved.
The resulting JARs have new identities and require their own startup/pairing proof.
The corrected Fabric notice is an explicit candidate overlay under
`tools/certification/notices/`; the historical source notice and its original
fixture-manifest pin remain unchanged. This avoids rewriting historical input
authority while correcting the separately selected candidate's actual bytes.

Before a separately approved installation, back up stopped worlds, configurations,
startup arguments and both accepted JARs. Verify the candidate manifest and use
Java 25, Minecraft 26.2, Purpur 2620, Fabric Loader 0.19.5 and Fabric API
0.161.0+26.2. Use the **same Purpur candidate file** as plugin and `-javaagent`:

```text
java -Xms256M -Xmx1536M -javaagent:plugins/achievetodo.jar -jar purpur-26.2-2620.jar --nogui
```

The diagnostic bridge/progression profile is explicitly experimental and must use
the separately qualified exact world/group/configuration bindings and externally
installed, authorized BACAP packs. This command alone does not approve a gameplay
rollout or enable the experimental profile. No default feature flags were changed.
Never mix old/new agent and plugin JARs. Stop before swapping either one.
Rollback restores the matching old pair and, if state must be reverted, the full
stopped backup. Notice-only changes alter no save schema; evidence of restart on
one copied qualification world is not an unrestricted upgrade guarantee.

Publication remains blocked until exact public redistribution and derivative-use
rights cover the selected payload, all required notices are approved, and the
owner approves metadata, selected hashes, integration target and publication.
