# R7 private reproducibility tooling

PRODUCT_GAMEPLAY_READY=false. No push, tag, PR, publication or deployment is authorized.
The approved Fabric and Purpur product binaries remain the S5 identities. These
tools do not modify production Java, resources, gameplay or historical authorities.

Use Python 3.14, Java 25, Gradle 9.8.0 and Loom 1.18.2. Obtain the separately sealed
R7 evidence and owner-supplied offline bootstrap bundle. The bundle remains private
and external to Git. Its exact file manifest, SHA-256 pin and classification are
in the R7 evidence. Verify the seal and manifest before executing tools.

Run `r7_bootstrap.py` with explicit `--source`, `--manifest`, `--manifest-sha256`,
`--bundle`, external `--home` and `--authority S5_R7_OFFLINE_BOOTSTRAP_V1`.
Every required selected dependency is bound to the unchanged 372-entry historical
manifest. Additional downloaded and locally generated prerequisites are separately
labeled. All content is checked before any write; verified atomic writes can be
resumed. This is offline provisioning of a reviewed cache snapshot. It is not
independent publisher authentication or proof of network-only cold acquisition.
The normal build verification gate has no exemption.

The two source-controlled archive authority files bind exact payload inventories,
generator revision, compression toolchain and metadata contracts. Their independently
sealed digest pins are mandatory arguments, not inferred from an untrusted file.
Use `r7_generated.py --kind minecraft|b10 --input ... --contract ...
--contract-sha256 ... --output ...`. Outputs must be new external paths.

Minecraft has two explicit outputs. The default canonical archive sorts entries,
uses 1980-01-01 timestamps, omits extras/comments, and uses pinned zlib deflate 9.
It has a new digest and is not admitted by historical Gradle metadata. With
`--restore-historical-envelope`, the tool instead reconstructs the old exact ZIP
from freshly validated compressed entry streams and an admitted historical envelope
template. That template contains headers, descriptors and central directory, but
no compressed class/resource streams. Reconstruction requires exact compressed and
uncompressed payload identities. It restores inherited metadata openly; it does
not claim that raw Loom independently reproduces the historical directory times.
Only the restored old digest is provisioned into a disposable project cache for
strict builds. The historical verification metadata is unchanged.

B10 uses real unmodified production conversion first. The external adapter then
checks all 7,092 names, every non-marker payload and all six marker properties.
It writes sorted ASCII property lines with LF and no comments, then canonicalizes
the ZIP. Unknown keys, changed values and unsupported metadata are rejected.
The resulting private fixture has a new authority; old B10 pins remain intact.
Runtime production conversion still emits its normal date comment. This adapter
is a reproducible offline conversion route, not a claim about raw runtime bytes.
Use the additive `r7.init.gradle` with the existing `r6.init.gradle` to execute
`r7ArchiveProbe` against raw input or canonical output. The probe calls the actual
compiled production generator/consumer. It adds no excluded JUnit methods.

The R7 evidence contains exact commands, contracts, faults, failed attempts,
source commits and profile-specific limitations. Keep strict verification on.
Do not use a successful offline run to assert network-only cold reproducibility,
nor a payload comparison to assert raw ZIP identity.

Public rights remain subject to the selected payload's retained licenses and
permissions. Project MIT does not override ARR translations. Purpur packaging
experiments remain separate from the accepted plugin/agent pair. Installation
requires the exact certified same-JAR agent/plugin identity and the existing
pinned runtime; never mix candidates. Preserve a private rollback copy of the
old binaries, configuration and world before any separately authorized rollout.
